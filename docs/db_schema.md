# Схема базы данных

Миграция: `kitchen-core/migrations/versions/0001_initial.py`. База — PostgreSQL 16.

```text
establishments 1───* categories
       │                 │
       ├─────────────* products
       │                 │
       └─────────────* orders 1───* order_items ─── 1 products
                            │
                            └───* order_status_history
```

| Таблица | Назначение и ключевые поля |
| --- | --- |
| `establishments` | Подключённое заведение. `partner_id` уникален и приходит из его системы; `callback_url` — адрес webhook; `status` определяет, доступен ли заказ. |
| `categories` | Категория меню заведения. Уникальность пары `(establishment_id, name)`. |
| `products` | Позиция меню. `external_id` — ID из POS, уникальный в рамках заведения; `stock = NULL` означает неограниченную позицию. Есть DB-проверки положительной цены и неотрицательного остатка. |
| `orders` | Заказ одного пользователя в одном заведении: адрес доставки, комментарий, снимок итоговой стоимости и текущий статус. Индексы поддерживают выдачу по пользователю и очередь заведения. |
| `order_items` | Позиции заказа и `price_snapshot`. Это сохраняет историю, если партнёр позже изменит цену. |
| `order_status_history` | Неизменяемый журнал переходов, используемый для трекинга клиентом и диагностики интеграции. |

## Модель состояний заказа

```text
created ──> accepted ──> preparing ──> ready ──> completed
   │             │
   ├──> cancelled└──> rejected
   └────────────────> rejected
```

Пользователь отменяет заказ только в `created`. Заведение принимает или отклоняет
`created`, а после принятия двигает заказ через подготовку и готовность. Любой
переход вне этого автомата получает `409 Conflict`.
